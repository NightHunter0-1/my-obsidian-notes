## Конспект

Базы данных - это набор порций информации, существующий в течение длительного времени. 
Данное определение очень обширно, поэтому в нашем случае термин будет немного усложнен. <font color="#4f81bd">Систему управления базами данных</font> (СУБД)

### Модели данных
Большинство объектов физического мира неимоверно сложны по своей организации. Когда мы пытаемся описать какой-либо из таких объектов, мы на самом деле придумываем модель, соответствующую ему в нашем понимании. Если объекты можно поделить на некоторые группы, удовлетворяющие одинаковым моделям, то мы получаем ситуацию. когда внутри базы данных хранятся две группы сущностей:
- Описание моделей объектов
- Записи, удовлетворяющие какой-либо из моделей и соответствующие различным представителям объектов
Но бывают ситуации, когда объекты настолько различны, что их нельзя классифицировать. Тогда база данных представляет из себя набор из одних лишь моделей. 
### Связи
Существует несколько видов взаимосвязей между объектами:
- один к одному - 1:1
- одни ко многим - 1:М
- многие ко многим - М:М

### Определение модели
<font color="#4f81bd">Модель данных</font> - это абстрактное, самодостаточное, логическое определение объектов, связей между ними, применимых к ним действий (операторов) и прочих элементов, в совокупности составляющих абстрактную машину, с которой взаимодействует пользователь. 

### Разновидность моделей данных
За долгую историю развития баз данных было разработано много вариантов организации информации. Вот основные из них:
- иерархическая модель
- сетевая модель
- реляционная модель
- объектная модель
- другие модели
На сегодняшний день актуальны, в основном, реляционная и объектная модели. Причем, хотя наибольшее распространение получила первая из них, обе модели имеют применение в современном программном обеспечении. 

### Реляционная модель 
В <font color="#4f81bd">реляционной модели</font> каждый вид объектов описывается при помощи таблицы. Таблицы в реляционной модели принято называть отношениями (отсюда и название: отношение по-английски - relation)

<font color="#4f81bd">Атрибуты отношения</font> - это столбцы таблицы

Каждая строка таблицы соответствует одному экземпляру объектов данного вида. Строки принято называть <font color="#4f81bd">кортежами</font> или <font color="#4f81bd">записями</font>.

### Ключ
<font color="#4f81bd">Ключом</font> называется набор полей, по значениям которых можно однозначно определить значения всех остальных полей строки. Если считать, что в таблице не бывает двух одинаковых строк, то можно сказать, что ключ обладает свойством уникальности. То есть значение ключа однозначно идентифицирует запись.
У одной таблицы может быть несколько ключей

### Первичный ключ
<font color="#4f81bd">Первичный ключ</font> - это наиболее часто используемый для поиска ключ таблицы. Каждая таблица может содержать только один первичный ключ

### Язык SQL
Язык SQL - это основной язык взаимодействия с информацией, размещенной  в реляционной базе данных. В той или иной модификации язык SQL есть во всех основных СУБД, но для каждой из них характерен свой диалект языка. (SQL для СУБД PostgreSQL)

Язык SQL позволяет создавать и манипулировать объектами реляционной БД. Например, SQL позволяет создавать таблицы, модифицировать их, наполнять строками, модифицировать строки, удалять строки и т.д.

### Составляющие языка SQL

### Синтаксис языка
Допустимо размещение любого числа проблемных символов (пробел, табуляция, новая строка) между двумя любыми лексическими конструкциями языка. 
Следующие два примера эквивалентны: 
```SQL
CREATE TABLE Test(id integer PRIMARY KEY, test varchar(16))
```

 ```SQL
 CREATE TABLE Test
 (
	 id integer PRIMARY KEY,
	 test
			 vaechar(
				 16
				 ));
 ```

Каждое выражение должно чем-то завершаться. В разных программных окружениях могут быть разные соглашения по этому вопросу. В pgAdmin4 выражение должно оканчиваться символом точки запятой ";".

Однострочные комментарии обычно указываются при помощи двух символов минус: "--". Многострочные комментарии можно размещать в любом месте:
```SQL
-- Создание таблицы
CREATE TABLE Test(
	-- Поле 1
	id integer PRIMARY KEY,
	-- Поле 2
	test varchar(16));
/* Удаление
   Таблицы */
Drop TABLE "test";
```

Обычно язык SQL нечувствителен к регистру букв. Основные команды можно писать как угодно. Но хорошим стилем, считается их написание заглавными буквами. Имена объектов (например, таблиц, полей), если они указаны без кавычек, автоматически преобразуются к нижнему регистру букв. Например, следующие два примера эквивалентны;
```SQL
CREATE TABLE test(
	id integer PRIMARY KEY,
	info char(16))
```
```SQL
CrEaTe table TEST(
	Id integer PRIMARY KEY,
	info char(16));
```
